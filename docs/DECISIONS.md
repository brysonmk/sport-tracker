## Process

- **Repo location.** The session started in an unrelated folder, so the repo was cloned to
  `~/Developer/sport-tracker` (owner chose this). All work happens there.
- **No AI co-author trailers in commits or PR bodies.** The owner asked for no
  Co-Authored-By trailer on commits in other repos ("for all future commits"), so commits
  here follow the same rule. The README's "How it was built" section is where the build
  process is described, because the brief asks for it.

## M1 Foundation

- **Upgraded Next 16.0.7 → 16.4.0 and React 19.2 → 19.3.** Same major versions as the
  brief, but with a year of bug and security fixes. Nothing in the skeleton depended on
  the older patch.
- **ESLint 9, not 10.** `eslint-config-next`'s plugins (react, import, jsx-a11y) only
  declare support up to ESLint 9; ESLint 10 installs with peer-dependency errors.
  Next 16 removed `next lint`, so `npm run lint` calls the ESLint CLI with a flat config.
- **`npm run typecheck` = `next typegen && tsc --noEmit`.** `next typegen` writes the route
  types (typed `params`, `PageProps`) without a full build, so typecheck works on a
  fresh clone.
- **Vitest 4 for unit tests, files next to the code (`foo.test.ts`).** Fast, native
  TypeScript, Jest-compatible API. Vite 8's built-in `resolve.tsconfigPaths` handles the
  `@/` alias, so no extra plugin.
- **Prisma 7.10 (stable), not the 8.0 release candidate.** npm's `latest` tag currently
  points at `8.0.0-rc.22`; a release candidate is not a foundation to build on.
- **Prisma 7 specifics.** Generated client lives in `src/generated/prisma` (gitignored,
  regenerated by `postinstall`). Settings live in `prisma.config.ts`. Queries go through
  the `pg` driver adapter, which works for both Docker Postgres and Neon, so local and
  production run the same code path.
- **Removed the AI "skills" folders that `prisma init` downloaded** (`.agents/`,
  `.claude/skills/`, `.windsurf/`, `skills-lock.json`). They are third-party agent
  instructions fetched from the internet, not project code.
- **Postgres 17 in Docker on host port 5433.** 5433 avoids clashing with any other
  Postgres already running on 5432.
- **Score is derived from events.** `Match` has no score columns. Each `MatchEvent` row is
  one goal (team credited, optional scorer, optional assist, optional minute). The
  score is a count of events, so score, standings and player stats can't disagree. An
  own goal or unknown scorer is a goal event with no scorer.
- **One row per goal, assist on the same row.** "Who assisted this goal" is a property of
  the goal, so a separate ASSIST row would need extra rules to keep the two in sync.
- **`MatchEvent.teamId` is stored, not read from the scorer.** Players can change teams;
  old results must not move with them.
- **Player names are unique per league.** Two "Mike"s on a stats table are confusing; the
  admin adds an initial ("Mike R.").
- **Admin token stored only as a SHA-256 hash.** A database leak doesn't expose admin
  links. A plain fast hash is enough because the token is 192 random bits (unguessable),
  unlike a user-chosen password.
- **Public slug = readable name + 4 random characters** (`tuesday-5s-k3x9`): shareable,
  readable in a chat, and two leagues with the same name don't collide.
- **Demo seed is deterministic and labelled.** Fixed slug `demo-league`, league named
  "Demo League (sample data)", invented names ending in Demo/Sample/Test/Mock/Example.
  Re-running replaces it. A new admin token is printed each run.
- **CI runs migrations and the seed against a Postgres service container**, so a broken
  migration or seed fails the PR, not the deploy.
- **Node 24 (`.nvmrc`)** for CI and Vercel: the current LTS line.

## M2 Core flows

- **Merges keep every commit** (`gh pr merge --merge`, not squash). The brief asks for small
  commits, and squashing would throw that history away.
- **Calculations are pure functions in `src/domain/`.** They take plain arrays and return
  plain arrays, so every standings/stats rule is unit-tested without a database.
- **Standings and player stats count FINISHED matches only.** A live 3-0 can still become
  3-3, so the table moves when the final whistle is recorded. The live match page shows
  the in-progress score separately.
- **Tiebreakers: points → goal difference → goals scored → head-to-head → shared
  position.** This is the Premier League order; it's the one most players already know.
  Head-to-head builds a mini-table from only the matches between the tied teams. Teams
  still level share a position (shown 1, 1, 3) and are listed alphabetically, instead of
  pretending the alphabet decided the ranking.
- **A player can't assist their own goal.** The form prevents it; the stats function also
  ignores it in case bad data gets in.
- **Teams can't be deleted while matches point at them (database RESTRICT).** So deleting a
  whole league must delete its matches first (they cascade to their goals), then the
  league (cascades to teams and players). The seed does this in one transaction. Tried
  `ON DELETE NO ACTION` to let one league delete cascade through everything; Postgres
  still fired the team check before the goals were gone, so it was reverted.
- **Server Actions for every write, Server Components for every read.** No REST API to
  maintain: a form posts straight to a typed function on the server. Each action re-checks
  the admin token, validates with zod, and filters every query by the league's id.
- **Admin token in the URL (`/a/<token>`), not a cookie.** The link works on any device
  and can be handed to a co-organiser. Admin pages send `Referrer-Policy: no-referrer` and
  `noindex` so the token doesn't leak through outgoing links or search engines.
- **Load the whole league per request.** One snapshot (teams, players, matches with goals)
  feeds every page. A rec league has tens of matches, so it's fast, and the table, stats
  and scores always come from the same data. React's `cache()` de-duplicates it between
  a layout and its page.
- **All league pages render per request (`ƒ` in the build output).** They read the
  database, which changes all the time; nothing is cached. The home page calls
  `connection()` for the same reason (it checks whether the demo league exists).
- **Dates are formatted in the browser** (`LocalTime`). The server runs in UTC and doesn't
  know the viewer's timezone. The kickoff input converts local time to ISO in the browser
  for the same reason.
- **Copy-link boxes build the full URL in the browser** from `window.location.origin`, so
  links are right on localhost, Vercel previews and production with no config.
- **React 19 resets forms after an action**, so failed submissions return the typed
  values (`FormState.values`) and inputs re-render with them. `<select>`s are keyed on
  that value because a select's `defaultValue` only applies when it mounts.
- **`/login` became `/open` ("Open a league")**: there are no accounts, so the page takes a
  pasted public/admin link and jumps to it (parsed in the browser, nothing sent).
  `/login` and `/matches-table` redirect permanently so old bookmarks still work.
- **Contact = GitHub issues.** No invented email address or contact form.
- **A goal's scorer list shows the scoring team's players first**, then "Other players":
  in pickup games people sometimes play for the other side.
- **Teams with matches can't be deleted; players can.** Deleting a team would rewrite past
  results. Deleting a player keeps their goals in the score as "unknown scorer".

## M3 Live match mode

- **Live updates: polling a tiny "version" endpoint, then `router.refresh()`.**
  Every public league page (via the league layout) runs `<LiveUpdates>`, which asks
  `GET /api/leagues/<slug>/version` every 3 s while a match is live (30 s otherwise). The
  version is "number of matches + newest `Match.updatedAt`", and every write that matters
  bumps `updatedAt`. When the version changes, `router.refresh()` re-renders the server
  components in place: no full reload, scroll position kept, and the page uses exactly the
  same rendering code as a normal visit.
  Why not the alternatives:
  - *WebSockets*: Vercel serverless functions can't hold open connections; it would need a
    separate service (Pusher, Ably, Supabase Realtime) plus an account and secrets.
  - *Server-Sent Events*: possible on Vercel, but each viewer holds a function open for the
    whole match (cost and duration limits) and it still needs a way to hear about writes.
  - *`router.refresh()` on a timer without the version check*: simpler, but re-renders the
    whole page every 3 s for every viewer even when nothing changed.
  Cost: one small aggregate query per viewer per 3 s during a match, nothing while the tab
  is hidden. Worst-case delay ≈ 3 s, which meets "within a few seconds".
- **Polling pauses while the tab is hidden** and checks immediately when it's shown again
  (phone unlocked, tab switched back).
- **An empty minute during a live match means "now"**: the server fills it from
  `startedAt` (`elapsedMinute`, unit-tested). The admin can still type a minute.
- **The live clock ticks in the browser** (`MatchClock`) from `startedAt`; no server round
  trip needed for the time.
- **Share image via the `opengraph-image.tsx` file convention** (next/og). Next adds the
  `og:image` tags itself. `metadataBase` uses `APP_URL`, else Vercel's
  `VERCEL_PROJECT_PRODUCTION_URL`, because chat apps need absolute image URLs. Chat apps
  cache previews, so a link shared mid-game can show an older score; that's accepted.
- **The score has `aria-live="polite"` while live**, so screen readers announce goals.

## M4 Ship it

- **Deploy target: Vercel + Neon, connected through Vercel's Neon integration.** The
  integration creates the database and stores the connection strings in Vercel, so the
  owner never copies a secret by hand. `prisma.config.ts` reads the direct URL from
  `DIRECT_URL` or the integration's `DATABASE_URL_UNPOOLED`.
- **Migrations run in the Vercel build** (`vercel-build`: `prisma migrate deploy && next
  build`). A deploy can't go live with code that expects columns the database lacks. If a
  migration fails, the build fails and the previous deployment keeps serving.
- **The app uses the pooled URL; migrations use the direct one.** Serverless functions
  open many short connections (the pooler handles that), but `migrate` needs a session-level
  lock that a transaction pooler can't hold.
- **Security headers on every response**: `nosniff`, `X-Frame-Options: DENY`,
  `Referrer-Policy: strict-origin-when-cross-origin` (other sites only ever see the origin,
  never an admin link's path).
- **Loading skeletons** for league and admin pages (`loading.tsx`). The league title and tabs
  come from the layout, so only the body shows a placeholder.
- **Accessibility pass**: skip link; repeated edit forms and delete buttons get unique
  accessible names ("Delete team Lions", "Name of Leo"); all theme colour pairs checked
  against WCAG AA (≥ 4.5:1); the light-mode LIVE red was darkened from 4.3:1 to pass.
- **README screenshots are generated** by `scripts/screenshots.ts` (Playwright) from the
  demo seed against a production build, so they can be re-taken after UI changes.
- **Demo kickoffs at 23:00 UTC** (7 pm Eastern) instead of whatever time the seed ran.
- **M4's deploy needs the owner's accounts, so M5 and M6 continue meanwhile.** The brief
  says to finish each milestone before the next, but the only M4 step left is one I can't
  do. Everything else in M4 is merged; the live link goes into the README once the
  account steps in docs/DEPLOY.md are done.
