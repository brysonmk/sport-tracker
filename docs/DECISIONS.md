## Process

- **Repo location.** The session started in an unrelated folder, so the repo was cloned to
  `~/Developer/sport-tracker` (owner chose this). All work happens there.
- **No AI co-author trailers in commits or PR bodies.** The owner asked for no
  Co-Authored-By trailer on commits in other repos ("for all future commits"), so commits
  here follow the same rule. The README's "How it was built" section is where the build
  process is described, because the brief asks for it.

## M1 Foundation

- **Upgraded Next 16.0.7 → 16.4.0 and React 19.2 → 19.3.** Same major versions as the
  brief, but with a year of bug and security fixes. Nothing in the skeleton depended on
  the older patch.
- **ESLint 9, not 10.** `eslint-config-next`'s plugins (react, import, jsx-a11y) only
  declare support up to ESLint 9; ESLint 10 installs with peer-dependency errors.
  Next 16 removed `next lint`, so `npm run lint` calls the ESLint CLI with a flat config.
- **`npm run typecheck` = `next typegen && tsc --noEmit`.** `next typegen` writes the route
  types (typed `params`, `PageProps`) without a full build, so typecheck works on a
  fresh clone.
- **Vitest 4 for unit tests, files next to the code (`foo.test.ts`).** Fast, native
  TypeScript, Jest-compatible API. Vite 8's built-in `resolve.tsconfigPaths` handles the
  `@/` alias, so no extra plugin.
- **Prisma 7.10 (stable), not the 8.0 release candidate.** npm's `latest` tag currently
  points at `8.0.0-rc.22`; a release candidate is not a foundation to build on.
- **Prisma 7 specifics.** Generated client lives in `src/generated/prisma` (gitignored,
  regenerated by `postinstall`). Settings live in `prisma.config.ts`. Queries go through
  the `pg` driver adapter, which works for both Docker Postgres and Neon, so local and
  production run the same code path.
- **Removed the AI "skills" folders that `prisma init` downloaded** (`.agents/`,
  `.claude/skills/`, `.windsurf/`, `skills-lock.json`). They are third-party agent
  instructions fetched from the internet, not project code.
- **Postgres 17 in Docker on host port 5433.** 5433 avoids clashing with any other
  Postgres already running on 5432.
- **Score is derived from events.** `Match` has no score columns. Each `MatchEvent` row is
  one goal (team credited, optional scorer, optional assist, optional minute). The
  score is a count of events, so score, standings and player stats can't disagree. An
  own goal or unknown scorer is a goal event with no scorer.
- **One row per goal, assist on the same row.** "Who assisted this goal" is a property of
  the goal, so a separate ASSIST row would need extra rules to keep the two in sync.
- **`MatchEvent.teamId` is stored, not read from the scorer.** Players can change teams;
  old results must not move with them.
- **Player names are unique per league.** Two "Mike"s on a stats table are confusing; the
  admin adds an initial ("Mike R.").
- **Admin token stored only as a SHA-256 hash.** A database leak doesn't expose admin
  links. A plain fast hash is enough because the token is 192 random bits (unguessable),
  unlike a user-chosen password.
- **Public slug = readable name + 4 random characters** (`tuesday-5s-k3x9`): shareable,
  readable in a chat, and two leagues with the same name don't collide.
- **Demo seed is deterministic and labelled.** Fixed slug `demo-league`, league named
  "Demo League (sample data)", invented names ending in Demo/Sample/Test/Mock/Example.
  Re-running replaces it. A new admin token is printed each run.
- **CI runs migrations and the seed against a Postgres service container**, so a broken
  migration or seed fails the PR, not the deploy.
- **Node 24 (`.nvmrc`)** for CI and Vercel: the current LTS line.
